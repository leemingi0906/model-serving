# 드리프트 설명 가이드 (발표용)

SolarCast 발표에서 "드리프트"를 설명할 때 쓰는 개념 정리, 우리 데이터에서 찾은 실제 사례, 판정 방법, 발표 흐름.
그림: `snapshots/41_v2_drift_cases_pr.png` (실제 사례 3건 + 10곳 월별 PR), 수치 근거: `experiments/drift_analysis.json`, `project_solar/logs/aiops.log`.

## 1. 한 문장 정의와 핵심 메시지

- **드리프트** = 모델을 학습시킨 세상과 지금 운영 중인 세상이 달라져서 예측이 어긋나는 것.
- 발표 핵심 메시지: **"오차가 커졌다 ≠ 모델이 틀렸다."** 태양광에서는 오차가 커지는 원인 대부분이 모델이 아니라 설비·날씨다.
  원인을 구분하지 않고 "오차 크면 재학습"을 하면 **고장 난 발전소를 정상으로 학습**해 버린다 (아래 6절, 광양항 실제 사례).

## 2. 교과서적 분류 → 우리 도메인 대응

ML 모니터링에서 쓰는 분류 (Gama et al. 2014, "A Survey on Concept Drift Adaptation", ACM Computing Surveys):

| 분류 | 뜻 | 태양광에서 해당하는 것 | 대응 |
|---|---|---|---|
| **Data drift / covariate shift** | 입력 분포 P(X)가 바뀜, 입력→출력 관계는 그대로 | 장마철·폭염 등 기상 분포 변화 | 재학습 불필요. 모델이 기상 입력을 받으니 그대로 맞춤 (장마철 PR 1.05) |
| **Concept drift** | 입력→출력 관계 P(Y|X)가 바뀜 | 여러 발전소가 동시에 "같은 날씨에 다른 발전량" (설비 증설, 제도 변경, 계측 기준 변경, 모델 노후) | **재학습** (최근 30일 fine-tuning → 게이트 → 재배포) |
| **Label/target 이상** (정답 쪽 문제) | 관계가 바뀐 게 아니라 특정 대상의 실제값이 비정상 | 설비 고장, 인버터 탈락, 오염, 계측기 이상 | 알림·현장 점검, **재학습 금지** |
| **Training-serving skew** | 학습 입력과 운영 입력의 품질 차이 | 학습은 관측 기상, 서빙은 하루 전 예보 | 드리프트 아님. 설계상 오차 상승 (8.29% → 9.85%). 예보 입력 학습으로 개선 가능 |

변화의 **모양**에 따른 분류 (같은 논문):

| 모양 | 형태 | 우리 사례 |
|---|---|---|
| Sudden (abrupt) | 하루 만에 계단형으로 바뀜 | 삼천포2 2025-12-16 PR 0.96 → 0.46 |
| Incremental | 몇 달에 걸쳐 천천히 한 방향으로 | 영흥#5 2026-03~08 PR 0.96 → 0.64 |
| Gradual | 옛 상태와 새 상태가 번갈아 나타나다 굳어짐 | 광양항 2025-08~09 (하락 중 간헐 회복) |
| Recurring | 바뀌었다가 원래대로 돌아옴 | 광양항 11월 복구, 삼천포2 1/9 복구 |

## 3. 태양광 도메인에서 원인별 "신호의 모양"

| 원인 | 오차율 | 성능비 PR (실제 ÷ 관측기상 기대치) | 몇 곳? | 시간 패턴 | 판정 |
|---|---|---|---|---|---|
| 날씨 예보 빗나감 | 커짐 | ≈ 1.0 (관측 기상 넣으면 맞음) | 한 지역 | 며칠 | weather → 알림 없음 |
| 설비 고장·인버터 정지 | 크게 커짐 | < 0.75, 급락 | 한 곳 | 계단형, 전 시간대 또는 특정 시간대 | equipment → `[ALERT]`, 재학습 차단 |
| 오염·노후·식생 그늘 | 서서히 커짐 | 0.75~0.92, 단조 하락 | 한 곳 | 몇 주~몇 달 완만 | soiling → 청소·점검 권고, 재학습 차단 |
| 모델 드리프트 | 커짐 | 여러 곳이 같은 방향 (예: 1.19~1.22) | 절반 이상 동시 | 동시 발생 | model_drift → fine-tune → 게이트 → 재배포 |
| 계측·데이터 품질 | 들쭉날쭉 | 피크 지연, 급변 | 한 곳 | 시간대 어긋남 | 데이터 검증에서 제외 (7곳 제외한 이유) |

업계에서 쓰는 같은 개념:
- 성능비 PR은 IEC 61724-1(태양광 성능 모니터링 표준)의 Performance Ratio와 같은 발상이다. 표준은 PR과 함께 **soiling ratio**(오염된 상태 출력 ÷ 깨끗한 상태 출력)를 측정하라고 권고한다. 우리는 센서 대신 모델 기대치를 분모로 쓴다.
- 미국 NREL의 RdTools는 일별 성능지수에서 "톱니 모양"(완만 하락 → 청소로 급회복)을 찾아 오염 손실을 추정한다(SRR, Deceglie 2018). 우리 감지기의 soiling 규칙(60일 단조 하락)이 이 톱니의 하락 구간을 보는 것과 같다.
- 일반 ML 모니터링 도구(PSI, KS 검정, ADWIN 등)는 입력 분포 변화를 본다. 태양광은 입력(기상)이 계절마다 당연히 바뀌므로 입력 분포 감시만으로는 장마철을 전부 드리프트로 오판한다. 그래서 우리는 **성능(제도 오차율) + 물리량(PR) + 동시성** 세 축으로 본다.

## 4. 우리 판정 방법 (의사결정 트리)

```
① 최근 21일 일 오차율 평균 > 임계값(max(8%, 검증 오차 8.29% × 1.25) = 10.36%) 인가?
   아니오 → ok
② 같은 시기(±7일) 다른 발전소도 절반 이상 임계값을 넘었나?  또는 21일 PR > 1.15 (실제가 기대보다 높음)?
   예 → model_drift → fine-tune(최근 30일, 해당 발전소) → held-out 게이트 → Production 교체
③ 60일 이상 기록에서 PR이 단조 하락 중인가?
   예 → soiling → 청소·점검 권고
④ 최근 7일 PR < 0.75 인가?  (급락 플래그)
   예 → equipment → [ALERT] 재학습 차단
⑤ 창 안에서 PR이 0.75~0.92로 −0.05 이상 완만 하락?
   예 → soiling
   아니오 → weather (PR 정상, 예보 오차) → 알림만
```

수식:
- 시간별 오차율 = |예측 − 실제| ÷ 설비용량 × 100 (발전량이 용량 10% 이상인 시간만, 제도 기준)
- 일 오차율 = 그 평균, 8% 이하면 정산 대상 (6% 이하 4원/kWh, 6~8% 3원/kWh)
- PR = Σ실제 ÷ Σ모델(관측 기상 입력) 기대치. 1.0이면 설비가 모델이 아는 정상 상태

## 5-1. 기후 변화(건기·우기화) 시나리오: 모의로 만든 방법과 결과

"장마는 모델이 안다(3년치 학습) → 드리프트 아님, 일시적 변동은 며칠이면 지나감 → 아님, 기후 변화로 생긴 새 패턴이 21일 이상 지속 → 드리프트, 단 관측 기상으로 다시 예측해도 틀릴 때만 재학습" 이라는 기준을 그대로 코드로 옮겼다.

| 시나리오 | 만든 방법 | 결과 (Production v1) | 판정 |
|---|---|---|---|
| A. 우기 패턴만 | 경남·경북 6곳의 장마철 2026-06-20~07-10 실적을 변형 없이 투입 | 오차 6.9~9.2%, PR 0.98~1.11 | 6곳 ok. 입력 분포는 바뀌었지만 기상→발전 관계는 그대로 → 모델이 흡수 |
| B. 폭염화 관계 변화 | 같은 6곳의 장마 직후 폭염 2026-07-20~08-09 실적에, 관측 기온이 28°C 를 넘는 시간마다 1°C당 −2.5% (36°C 면 −20%) 손실을 넣음 | 경남 4곳 오차 11.4~16.0%, PR 0.72~0.78 / 경북 2곳 오차 9.3~9.9%, PR 0.88 | 4곳 model_drift(동시성 0.67) → fine-tune → 게이트 통과 → v2 승격 |

발표에서 짚을 점 세 가지:
- **같은 날씨, 다른 발전량이 "여러 곳에서 동시에"** 나타나야 모델 드리프트다. 한 곳이면 설비, 모두면 기후·제도·계측 변화. B 에서 더운 경남 4곳만 임계값을 넘었고 경북 2곳은 이내였다. 지역 경사까지 재현된다.
- **우기화 자체는 드리프트가 아니었다.** 같은 20% 손실을 장마철 창에 넣어 봐도 오차율이 8.5~9.2%에 머물러 임계값(10.36%)을 넘지 않는다. 제도 오차율이 설비용량 대비 절대 오차라서, 흐린 날의 비례 손실은 작게 잡힌다. 기후 시나리오를 맑은 폭염 창에 둔 이유다.
- **모의임을 명시한다.** 실제 1년 데이터에는 동시 변화가 없었다(그림 ④). 기온 의존 손실은 "폭염이 길어지면 모듈 온도 손실이 과거보다 커진다"는 가정을 숫자로 만든 것이고, 계수(−2.5%/°C)는 PR 0.75~0.9 범위에 들어오도록 고른 값이다. 조원이 다른 가정(연무, 적설 지속 등)을 원하면 `/data/window` 의 `heat_loss`, `heat_base`, `scale` 조합으로 바꿀 수 있다.

## 6. "오차만 보고 재학습하면 생기는 일" (발표 포인트)

광양항은 2025-08~10 고장 구간이 학습 데이터 끝(테스트 분할 2025-09-01 직전)에 섞여 있다. 그 결과 모델은 광양항을 "원래 PR 0.3~0.4짜리 발전소"로 배웠고,
11월 설비가 복구되자 PR이 1.15~1.22로 튄다(그림 ④ 파란 선). 즉 **고장을 정상으로 학습하면 복구 후에 반대로 틀린다.**
감지기는 이 세 건 모두에서 `[ALERT]`만 남기고 재학습을 막았고, 재학습은 세 곳이 동시에 같은 방향으로 바뀐 합성 시나리오에서만 발동했다.

같은 함정이 재학습 안에도 있다. 전 발전소 변화와 영흥#5 저성능이 같은 3주에 겹치자 동시성 규칙이 영흥#5까지 "모델 드리프트"로 묶어 fine-tune 데이터에 넣었고, 새 모델 오차가 10.41%에서 10.95%로 나빠졌다.
그래서 재학습 대상에서 PR < 0.75 인 발전소는 제외하도록 고쳤다(`retrain_trigger.py`, 로그에 `excluded low-PR plants` 로 남는다). 발표에서 "드리프트 대응도 데이터 선별이 핵심"이라는 근거로 쓸 수 있다.

## 7. 발표 흐름 제안 (5장)

1. **문제**: 제도는 오차 8%로 정산. 운영하면 오차는 반드시 커진다. 왜? 세 가지 이유(날씨, 설비, 모델).
2. **그림 ④**: 1년 동안 10곳이 동시에 틀린 달은 없었다 → 모델은 멀쩡했고, 틀린 건 개별 발전소.
3. **그림 ①②③**: 세 가지 모양(정지, 계단, 점진). 각각 PR과 동시성으로 어떻게 구분했는지.
3-1. **기후 변화 모의 A/B**: 우기 패턴만은 ok, 폭염화 관계 변화는 4곳 동시 → 재학습 → v2. "모델이 아는 변화"와 "모르는 변화"의 차이.
4. **의사결정 트리 + 대시보드 로그**: 설비는 `[ALERT]`, 전 발전소 변화만 `[INFO] retrain triggered` → `[OK] promoted v2`.
5. **교훈**: 오차만 보면 안 된다. 광양항 PR 1.2 사례. 그리고 한계(용량 추정값, 예보 입력 격차 1.5%p, 계측 불량 7곳 제외).

예상 질문:
- "왜 PSI 같은 표준 드리프트 지표를 안 썼나?" → 입력(기상)은 계절마다 당연히 바뀐다. 입력 분포 감시는 장마철을 드리프트로 오판한다. 성능·PR·동시성이 도메인에 맞다.
- "재학습 기준이 너무 보수적이지 않나?" → 재학습은 고장을 정상으로 배우는 위험이 있다. 챔피언/챌린저 게이트로 좋아질 때만 교체한다.
- "오염과 고장은 어떻게 구분?" → 속도. 하루 만에 떨어지면 고장, 몇 주에 걸쳐 단조 하락이면 오염. 영흥#5는 둘 다 가능해 현장 확인 항목으로 남겼다.
- "모델 드리프트는 실제로 언제 생기나?" → 설비 증설·교체(용량 변경), 계측 기준 변경, 제도 변경, 발전소 추가. 우리 데이터 1년에는 없었고 합성으로 검증했다.
